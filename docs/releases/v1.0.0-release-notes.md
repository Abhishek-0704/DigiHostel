# Reception Dashboard v1.0.0 — Release Notes

**Release commit**: `39e91c881eeabfd178e384d1da058a824de2e408` (`main`)
**Release date**: 2026-09-24
**Certification basis**: QG-06 Enterprise Go-Live & Deployment Readiness Certification — **GO-LIVE APPROVED WITH MINOR ACTION ITEMS**, plus Prompt 19 (Testing, QA & Release Hardening) — **RELEASE CANDIDATE READY WITH MINOR ACTION ITEMS**.

This document describes what v1.0.0 actually contains, evidenced against the repository and live production infrastructure — not a forward-looking roadmap. For the full evidence trail behind any claim below, see the linked documents; this file summarizes rather than duplicates them.

## What's included

### Authentication & Security Architecture

- Supabase Auth password sign-in + mandatory native TOTP MFA, enforced to AAL2 for every sensitive/administrative operation (ADR-024).
- Role-based access control (`reception_warden`, `hostel_admin`, `library_incharge`, `super_admin`) enforced at both the Fastify application layer and the database layer (Row-Level Security on all 27 public tables).
- Hostel-scoped authorization — staff see and act on only their own hostel's data, except `super_admin`, which is intentionally global.
- Force Sign-Out (session invalidation for a targeted staff member), independently live-verified against production this release cycle: target session killed instantly, unrelated sessions unaffected, self-targeting blocked, database mutation confirmed.
- Full authentication chain (password → AAL1 → TOTP → AAL2 → authorized access) independently live-verified against real production infrastructure.

### Reception Operations

- Leave Request Queue with search, filter, and sort, live-updating via Realtime.
- Parent Approval Session workspace, including reception-initiated triggering of the parent-approval/escalation process.
- Student Operations Center (search, profile, guardian contact, current leave status).
- Movement Engine (Hostel Return recording) with derived, never-persisted hostel-presence state.
- Student Verification & Exit Authorization, with a database-enforced state gate (exit authorization requires the leave to already be `approved`).
- Emergency Operations Center and Health Operations Center, each with a full incident/case lifecycle, realtime updates, and staff-initiated reporting.

### Administration

- Identity & Access Administration Center — staff directory, provisioning (via Supabase Auth Admin API invite), role/hostel reassignment, suspend/reactivate, Force Sign-Out, with last-active-`super_admin` protection.
- Enterprise Configuration Center — a generic, audited key/value configuration store with optimistic-concurrency updates (values stored and editable; runtime consumption by application code is explicitly deferred, not fabricated).
- Administrative Profile & Personal Preferences Center — self-service profile/preferences, session management.

### Visibility & Compliance

- Enterprise Audit Center — a privileged, hostel-scoped read surface over the existing `audit_logs` trail, covering every module that writes to it.
- Enterprise Operations Monitoring Center — `super_admin`-only platform/application/security health overview and a fixed, allow-listed diagnostic suite. Deliberately reports `unknown`/`unavailable` rather than fabricating a signal it can't genuinely measure.
- Operational Intelligence & Executive Analytics Dashboard, and the Enterprise Reporting Platform (a fixed report catalog with server-validated filters and personal saved templates — not a general-purpose query builder).

### Deployment & Infrastructure

- Genuinely separate production infrastructure: Vercel Production (frontend), Render Production (`digihostel-api-production`), and Supabase Production (`asphlfoikqyaeslmhrah`), independently verified isolated from staging.
- A repeatable, `main`-restricted, GitHub Actions-controlled production release workflow (`deploy-production.yml`): migration application → Render deployment → health/provenance verification, structurally protected at both the workflow and GitHub Environment level.
- Migration governance: exactly one proven, authoritative migration path for production.

## Known Limitations (governed, not hidden)

## Explicitly not included
